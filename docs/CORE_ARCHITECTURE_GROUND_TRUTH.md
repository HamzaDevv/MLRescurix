## Objective and boundaries

MLRescurix aims to help develop and evaluate general ML models and tackle Kaggle problems, including custom neural and sequential models. Rust is the preferred control-plane language; Python is appropriate for scientific and training libraries. The user will select five distinct benchmark problems later. A cart transformer was an example, not a mandatory target. Finite resources prevent an unconditional guarantee that any problem will run or succeed: the desired behavior is bounded execution, resumable progress where supported, and a clear `needs_resources` or unsupported result.

This repository has a Rust harness and Python scientific worker, with different degrees of integration across paths. The presence of a module, contract, mock or synthetic result does not establish end-to-end operation for arbitrary workloads.

## Trust and resource findings

1. `container_scientific_worker` mounts the entire workflow directory writable into the container. A development-only CSV mount does not prove the worker cannot read sealed data or mutate trusted files elsewhere in that directory. The generated development file also uses a shared workflow path; concurrent jobs and failed partial writes need isolation. The raw file is hashed and reopened for parsing, so immutable snapshot and time-of-check/time-of-use handling still matter.
2. Evaluation and promotion must bind authoritative dataset, protocol, job, candidate, source, environment and weights to an independently checked result. A self-reported worker score, matching worker-generated hashes or a passing fixture alone cannot prove this. Re-review the new `Supervisor::finish` checks and their negative cases before reopening admission.
3. The locally present pinned Docker image was used in historical synthetic tests. Its ignored wheelhouse is not included in Git; reproducible provisioning on a clean machine, target platform compatibility and GPU support are not established.
4. Tuning and provider routes should be treated as experimental until every dispatch is governed, reservations cover each potentially billable attempt, uncertain outcomes are reconciled, and subprocess time/resource limits actually terminate work. Provider billing is not established by local estimates.
5. Claims of universal sealed-data safety, exact replay, 80–98% context compression, all-job governance, zero-dependency delivery, complete support for all modalities, or guaranteed success lack evidence for the whole system. Apply those claims only to a defined path with a reproducible measurement.

## Offline engineering follow-up (2026-10-29)

`prepare_dev_dataset` now hashes the exact stream consumed by its CSV parser using a single open handle, rejects a final-component raw symlink, and writes a private temporary file before exclusive hard-link publication. Parsing, split and hash failures remove the temporary output; existing destinations are not overwritten. Focused tests cover malformed data, hash mismatch, symlinks and competing publication. This assumes a trusted destination directory and does not create a per-job immutable raw snapshot, bind an authoritative manifest to a job, isolate the shared workflow, or implement trusted evaluation. An interrupted process can leave an unpublished temporary file, and a directory-sync failure after publication has an ambiguous outcome requiring reconciliation. The custom admission gate remains closed.

Focused verification in this follow-up: `cargo test --offline --test custom_model_gate test_dev_splitter -- --nocapture` passed 4 tests; `cargo test --offline --test custom_model_gate --test kaggle_gate` passed 16 custom tests (3 ignored behind the admission gate) and 7 mock Kaggle tests. `python3 -m pytest python/tests/test_review_safety_regressions.py python/tests/test_session2_kaggle_execution.py python/tests/test_session3_tuning_and_delivery.py python/tests/test_ml_task_adapters.py -q` passed 41 tests. `git diff --check` passed; `cargo fmt --all -- --check` could not run because cargo-fmt is not installed. ## Additional offline local-safety work (2026-10-29)

Rust now has a controller-side frozen protocol store (`custom_protocol.rs`), per-job input snapshot preparation (`custom_snapshot.rs`, `development_inputs.rs`), and a bounded numeric metric primitive (`trusted_evaluation.rs`). Synthetic tests exercise conflicting freezes, restart, split and dataset identity mismatches, tampering, incomplete and concurrent snapshot publication, validation-label exclusion, and mismatched or non-finite predictions. The legacy `Supervisor::finish` custom-evaluation path now rejects worker-reported metrics rather than recording them as evaluated, and custom export refuses legacy evaluations as promotion authority. Exit 137 is no longer attributed to memory pressure without evidence.

These components are **not integrated into custom admission, container mounts, supervised inference, promotion or checkpoint recovery**. The snapshot root and ancestors must be trusted, interrupted preparation directories require explicit reconciliation, and source/environment/weights identities are not yet independently verified by these helpers. A matching prediction identity is not proof that the stated model produced the predictions; snapshot creation must also be restricted to the trusted registered-dataset preparation path before its labels can be authoritative. Supported primitive metrics are numeric accuracy, MAE, MSE and RMSE only. The protocol and snapshot storage formats require independent security review; keep custom admission disabled.

Focused command: `cargo test --offline --test custom_snapshot --test custom_protocol --test development_inputs --test trusted_evaluation` passed 9 tests. `cargo test --offline --test custom_model_gate --test trusted_evaluation` passed 17 custom tests (3 ignored) and 2 evaluator tests before the additional snapshot changes.

Full Rust regression after the protocol and snapshot work: `cargo test --offline` exited successfully, with configured ignored tests. The final checkpoint-identity validation and additional fabricated-row test were also covered by the focused commands above; live provider tests remained ignored.
