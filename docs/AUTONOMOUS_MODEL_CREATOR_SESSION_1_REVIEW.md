# Session 1 independent review

Verdict: foundations exist, but W0, W1 and W3 have not met the master plan's acceptance gates. Do not treat this batch as a completed routing, assessment or evaluation authority. The following are priorities for the next implementation batch; retain the plan's remaining W2–W9 work in scope.

1. **Provider routing and spend controls are not integrated.** `dispatch_gateway_with_routing` accepts an already constructed gateway and changes only the model identifier; the resolved endpoint, credentials, adapter protocol, disclosure rules, role spend limits and fallback are not used to select or constrain transport. The production CLI still calls `dispatch_gateway_with_id`, and the legacy benchmark path still hardcodes a provider/model. The new offline fixture only checks a returned routing label. The old live route and price-cap restrictions were removed without an equivalent configured provider/route authorization: the new check is optional and only runs when `max_price` is an object. Restore fail-closed authorized routing and provider-side price bounds before live use, then integrate profile-aware dispatch, correct provider-aware pricing and conservative token admission. Handle pricing registration errors rather than discarding them. Add tests that verify the actual transport destination and request, unsupported protocols and capabilities, disclosure, bounds and fallback, including rejection before outbound I/O. Context estimation as bytes/3 is not an upper bound. Python still contains default pricing/translation and governance's `or` fallbacks can override a configured zero budget; replace duplicate authority per W1.

2. **Assessment and splits are not an enforced end-to-end boundary.** `carve_lockbox`, `generate_k_fold_splits` and `consume_assessment` have no non-test callers. Consumption records only project/dataset/time and does not bind a frozen artifact, inference, score or durable receipt; the ordinary scorer does not require consumption. `canonical` checks fold train/validation overlap and lockbox membership, but does not reject duplicate fold IDs or duplicate rows within a fold, unknown rows, or test rows in folds, and does not enforce declared time/group semantics. It still requires a nonempty legacy test split. The hard 20-row cutoff is not task-specific feasibility. Implement and test the complete frozen assessment lifecycle and validation semantics under the authoritative writer, including concurrent/crash cases and adversarial access paths, before claiming isolation or one-shot scoring.

3. **Evaluation assurance and metric semantics are overstated.** Every score is labeled `reference_conformant` without evidence of reference validation, including legacy receipts deserialized without the field. The plan reserves that claim for recorded conformance evidence. The scorer remains a closed enum, F1's threshold is fixed, and class mapping and metric conventions are not bound in a frozen MetricSpec. ROC-AUC merges distinct scores within 1e-15 as ties; exact ranking need not do so. SMAPE rejects negative values although the formula's absolute-value denominator can support signed values; the variant and domain must be explicit. Implement evidence-bound assurance, extensible evaluator admission and task-specific conventions; add independent reference and boundary tests.

4. **Schemas and tests do not demonstrate the claimed integration.** The Python schema tests parse JSON and check for required keys in hand-built dictionaries; they do not validate instances against the schemas or Rust serialization, nor exercise transport. W0 also lacks several planned schemas and a deletion/dependency inventory; W1 lacks accounting/writer reconciliation and the 50-task campaign; W3 lacks independent custom evaluator/splitter admission and pre-search lockbox enforcement. Compare all acceptance criteria in the master plan and report partial status precisely.

5. **Documentation cleanup needs follow-through.** The removal includes tracked pointer stubs and untracked historical plans, review source text and live-exercise reports. Some latter material was never in Git, so it cannot be recovered from Git. Preserve available original attachments and do not claim the deleted evidence was duplicated without verifying it. `scripts/build_argon_review_packet.py` still describes and searches for deleted v2 planning files while reporting an inaccurate source count; decide whether to remove or replace that obsolete script and inspect other dependents. Historical evidence manifests mention deleted paths; keep their provenance truthful. The continuation guide's active link to the deleted prompt was corrected during this review.
