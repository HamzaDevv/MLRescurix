# Autonomous Model Creator — Session 4 independent review

Verdict: **work in progress; the production vertical slice and the master plan are not complete.** Session 4 improves some primitives, and its synthetic test now produces runnable predictions. Its handoff overstates what is implemented and verified. Read this review alongside the handoff; where they conflict, this review records the actual limitations and reviewer changes.

## Findings

1. **No governed end-to-end production path or physical label isolation.** `crates/harness/tests/governed_source_execution.rs` constructs the dataset, policy, manifest, model and bundle inside a test. A scripted provider fixture returns the hard-coded `solution_code` through the real orchestrator; it does not demonstrate independent model design by an agent. At lines 484–496 it checks sandbox refusal separately, but at lines 505 and 526 it executes the model with host `Command::new("python3")` regardless. Both the worker workspace and controller's private data are accessible to that host process. Separate subprocesses and directories are not a security boundary. The actual production entry points do not connect problem ingestion, model authoring, isolation, split/label custody, scoring and delivery. The passing test is useful as a synthetic integration exercise, not proof of the claimed autonomous system.

2. **Reference assurance was self-certified again (reviewer fixed).** The added in-memory registry allowed any caller to register its own expected score and arbitrary receipt digest as a trusted fixture. The integration test did precisely that and asserted `reference_conformant`. A map named trusted does not establish an independent source, and its metric version was not bound to the evaluated spec. The reviewer removed this unverified registry and certification path; matching caller evidence remains provisional. Implement independently admitted, durable, content-bound reference evidence and test its actual authority before restoring conformance claims. Custom evaluators are currently an in-process public registry, not a governed admission and isolation mechanism.

3. **Spend and credential safety have unresolved cases.** Session 4 prevents rewriting settled spend and improves pricing locks and namespacing. However, its error cleanup deleted `reserved` accounting for any status other than `outcome_unknown`; a concurrent duplicate can encounter `awaiting_response` while the first call is in flight and delete that call's reservation. A failed receipt write following remote dispatch has the same risk. Reviewer changed cleanup to retain reservations unless recovery establishes the outcome and added a synchronized regression test. This conservative fix may leave reservations stranded; implement durable reconciliation for pre-dispatch, in-flight, response-received and uncertain states, including accounting after receipt persistence and crash recovery. The default role policy still allows no role spend limit, and a caller-generated policy does not establish campaign authority. Reviewer also restricted automatic OpenRouter secret lookup to the exact effective HTTPS authority `openrouter.ai`: substring checks and endpoint overrides could otherwise disclose the default key to another endpoint. Explicit caller-supplied keys and provider secrets remain caller-controlled; further endpoint and disclosure policy tests are needed.

4. **Assessment and split protections are incomplete.** `evaluate_and_consume_assessment` still allows caller labels when a registered dataset row/path is unavailable or empty; only the separate authoritative helper requires a file. Its one-shot check and score calculation occur before the transaction that consumes the lockbox, so concurrent callers can both access and compute a score, although only one consumption can commit. Binding to hashes does not prove the frozen candidate actually produced predictions. `freeze` only derives group/time metadata if the path exists and can accept absent maps otherwise; `verify_authoritative_fit_scope` accepts omitted feature/exclusion/evaluation row sets and has no production caller. Bind these operations to controller-owned dataset, split and execution evidence, fail closed when required metadata is unavailable, and enforce lockbox claim before accessing labels or computing scores. The CSV reader and legacy column migration are improvements, but need adversarial compatibility and concurrency tests through the production path.

5. **The model and recovery demonstrations are test-specific.** The test constructs its inference implementation and bundle by hand for one hard-coded two-feature model; the JSON weights are named `frozen_model.joblib`, though the generated inference script reads JSON. CLI and serving checks demonstrate that particular test artifact works, not generic delivery for arbitrary agent-authored models. Dropping an uncommitted transaction and reopening a connection is not a process-kill/restart test across dispatch, scoring and delivery. Build artifact production from the actual selected agent program, test inference parity on a fresh environment, and perform real fault injection at meaningful crash boundaries.

6. **Scope is much larger than the handoff's final-session list.** Kaggle backend and compliant account/quota handling, local fallback, agent-driven research and portfolio experimentation, multiple provider routing under a true authority, evidence-bound artifact selection and final reports remain to be demonstrated against the master plan. Do not equate passing fixture tests with those capabilities. Preserve flexible agent-authored workflows and remove replaced legacy logic only after checking live dependencies.
